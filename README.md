## Purpose

This R Markdown project performs a reproducible differential expression analysis on gene-level read counts from six assigned samples, three from condition A and three from condition B.

Sample metadata are manually constructed from sample ID and condition. Counts are read, merged into a count matrix, and checked to ensure correct alignment with the metadata. HTSeq summary rows are separated from gene counts, and library sizes, read-assignment statistics, sequencing depth, assignment rates, and count distributions are assessed for quality control before normalisation and differential expression analysis.

The count data are prepared by removing unexpressed and low-count genes, normalising to counts-per-million (CPM), and applying a log₂ transformation. Principal component analysis (PCA) is performed on the normalised expression data to identify major sources of variation, quantify variance explained, and assess clustering by experimental condition.

Differential expression analysis is performed using DESeq2 for condition B versus condition A. Raw counts are modelled using a negative binomial framework with size-factor normalisation and gene-specific dispersion estimates, and log₂ fold changes are shrunk using apeglm.

Genes are classified as up-regulated in condition B, down-regulated in condition B, or not significant using thresholds of adjusted p-value < 0.05 and absolute log₂ fold change > 1. Results are visualised with a volcano plot and row-scaled heatmap. Systematic identifiers are mapped to common gene names and functional descriptions using `org.Sc.sgd.db`, and significant genes are compared against the tested gene universe using GO Biological Process over-representation analysis. The assigned gene of interest is then extracted from the differential expression results, including its shrunken log₂ fold change, adjusted p-value, significance classification, common gene name, and associated Gene Ontology Biological Process annotations.

The project is designed to knit reproducibly on the Deakin Linux SLE777 bioinformatics server. The assigned count files, the count files directory, and gene of interest are declared and saved in the parameters at the beginning of the project. The six count files are read directly from the shared server path `/home/shared/SLE777/A4_counts` and are not included in the submitted project folder.

## Reproducing and knitting the report

A reader with only the submitted `24_A4` folder can reproduce the analysis on the Deakin Linux bioinformatics server. The six assigned count files are not stored in the submitted folder; `24_report.Rmd` reads them directly from the shared server path `/home/shared/SLE777/A4_counts`.

After unpacking the submission, move into the project folder:

```bash
cd 24_A4
```

The report can then be knitted from the command line with:

```bash
Rscript -e 'rmarkdown::render("24_report.Rmd")'
```

Alternatively, open `24_report.Rmd` in RStudio on the server and select **Knit**.

The report is designed to knit from a clean copy of the submitted folder without editing paths or manually inserting outputs. A successful clean knit should reproduce `24_report.html`, the numerical results used in `24_results.csv`, and the required figures generated by the report code. Read permissions are required for both the .Rmd, the count files directory, and write permissions are required for the 24_A4 folder, although this can be created newly by the user (`mkdir -p 24_A4`).
